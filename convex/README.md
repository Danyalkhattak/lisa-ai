# Convex backend for Lisa AI

This folder contains the entire Convex backend — schema, auth helpers,
Clerk webhook handler, and all queries/mutations. It's **Section 5** of
the Lisa AI build.

## File map

| File | Purpose |
|---|---|
| `schema.ts` | Defines all four tables (`users`, `conversations`, `messages`, `userSettings`) and their indexes |
| `auth.config.js` | Tells Convex to trust Clerk-issued JWTs |
| `auth.ts` | Shared `requireAuthedUser` / `requireClerkSubject` helpers used by every protected function |
| `lib.ts` | Pure helpers and constants (`DEFAULT_SETTINGS`, `MAX_FREE_MESSAGES_PER_MONTH`, `sanitizeTitle`) |
| `clerkWebhook.ts` | Internal mutations called from `http.ts` to upsert/delete users on Clerk events |
| `http.ts` | HTTP router + Svix signature verification for `/clerk-users-webhook` |
| `conversations.ts` | Conversation CRUD: list, listPinned, get, create, rename, setPinned, softDelete, restore, permanentDelete, search |
| `messages.ts` | Message CRUD: list, send, saveAssistantMessage, remove, clear |
| `users.ts` | User profile: getMe, updateProfile, setPlan |
| `userSettings.ts` | Per-user preferences: get, update (lazy upsert) |
| `stats.ts` | Usage stats: conversationCount, messagesThisMonth, totalMessages, pinnedCount, lastActivityAt |
| `_generated/` | Auto-generated by `convex dev` — never edit by hand |

## Schema overview

```
users              clerkId (indexed, unique)
                   email, name, imageUrl, plan
                   createdAt, updatedAt

conversations      userId (Clerk ID, indexed)
                   title, pinned, deletedAt (soft delete)
                   lastMessageAt, messageCount
                   createdAt, updatedAt
                   Indexes: by_user, by_user_pinned, by_user_recent

messages           conversationId (indexed)
                   userId (denormalized Clerk ID)
                   role: user | assistant | system
                   content
                   toolName? + toolResult? (structured tool output)
                   createdAt
                   Indexes: by_conversation, by_user

userSettings       userId (Clerk ID, unique)
                   voice, language, inputLanguage
                   speechRate, geminiModel, autoSpeak
                   updatedAt
```

## First-time setup

### 1. Install the Convex CLI

Already in `package.json` — just run `npm install`.

### 2. Create a Convex deployment

```bash
npx convex dev
```

This will:
- Prompt you to sign in to Convex (free tier is fine)
- Create a new deployment (or link to an existing one)
- Generate `.env.local` with `VITE_CONVEX_URL=` for the client
- Generate the `_generated/` folder in `convex/` from `schema.ts`
- Watch for changes and hot-reload function code

### 3. Add the Clerk secret

The webhook handler needs `CLERK_WEBHOOK_SECRET` to verify incoming
requests. Set it on the Convex deployment (not in `.env.local` —
Convex server-side env vars are managed via the CLI):

```bash
npx convex env add CLERK_WEBHOOK_SECRET
# Paste the signing secret from Clerk dashboard → Webhooks → your endpoint
```

### 4. Configure Clerk

In the Clerk dashboard:

1. **API Keys** → copy your **Frontend API URL** (looks like
   `https://your-instance.clerk.accounts.dev`).
2. Convex dashboard → Settings → Auth → Add provider → Clerk → paste
   the Frontend API URL.
3. **Webhooks** → Add endpoint. The URL is:
   ```
   https://<your-convex-deployment>.convex.site/clerk-users-webhook
   ```
   Subscribe to:
   - `user.created`
   - `user.updated`
   - `user.deleted`
4. Copy the signing secret and run `npx convex env add CLERK_WEBHOOK_SECRET`.

### 5. Add client-side env vars

In `.env.local` (already templated in `.env.example`):

```bash
VITE_CLERK_PUBLISHABLE_KEY=pk_test_...
VITE_CONVEX_URL=https://your-deployment.convex.cloud
```

### 6. Run the app

```bash
npm run dev          # Vite dev server
npm run convex:dev   # Convex backend (run in a separate terminal)
```

## Function reference

### `conversations.*`

| Function | Type | Purpose |
|---|---|---|
| `list` | query | All conversations for the current user, newest first |
| `listPinned` | query | Pinned conversations only (sidebar) |
| `get` | query | Single conversation by ID (returns null if foreign) |
| `create` | mutation | New conversation, returns its ID |
| `rename` | mutation | Update title (sanitized) |
| `setPinned` | mutation | Toggle pinned state |
| `softDelete` | mutation | Move to trash (recoverable) |
| `restore` | mutation | Restore from trash |
| `permanentDelete` | mutation | Cascade delete conversation + all messages |
| `search` | query | Substring search across titles |

### `messages.*`

| Function | Type | Purpose |
|---|---|---|
| `list` | query | Messages in a conversation, oldest first |
| `send` | mutation | Persist a user message + bump conversation stats |
| `saveAssistantMessage` | mutation | Persist an assistant reply (called by the AI action in Section 6) |
| `remove` | mutation | Delete a single message |
| `clear` | mutation | Delete all messages in a conversation (keeps shell) |

### `users.*`

| Function | Type | Purpose |
|---|---|---|
| `getMe` | query | Current user's profile (with `pendingSync` flag) |
| `updateProfile` | mutation | Update name / imageUrl (app-local override) |
| `setPlan` | mutation | Update plan (demo affordance — Stripe gates this in production) |

### `userSettings.*`

| Function | Type | Purpose |
|---|---|---|
| `get` | query | Current user's settings (defaults if no row) |
| `update` | mutation | Lazy-upsert settings row |

### `stats.*`

| Function | Type | Purpose |
|---|---|---|
| `getUsage` | query | conversationCount, pinnedCount, messagesThisMonth, totalMessages, lastActivityAt |

## Security model

Every protected function calls `requireClerkSubject(ctx)` (or
`requireAuthedUser` when the row is also needed) before doing any work.
This:

1. Reads the Clerk identity from the JWT (validated by Convex using
   `auth.config.js`).
2. Looks up the user row in the `users` table.
3. Throws if either step fails — no function ever returns data for a
   user that isn't signed in.

Per-user ownership is enforced by filtering on `userId === clerkId`
on every query and mutation. A user can never read or mutate another
user's conversations or messages.

## What's NOT in this section

- **Gemini AI integration** — that's Section 6. The `messages.send`
  mutation persists the user message but does NOT call Gemini; the
  client will call a separate action (added in Section 6) to generate
  the reply and persist it via `messages.saveAssistantMessage`.
- **Stripe webhooks** — that's a later section. `users.setPlan` is a
  demo affordance for now.
- **Scheduled jobs / cron** — none yet. If usage stats become hot,
  we'll add a cron to materialize them into a `usageStats` table.
